# Verdict on scenario "#US0.05 AC3 the submission is published once, as an integration event carrying the application identifier, in the same transaction that records it"

Story: US0
Subject: scenario "#US0.05 AC3 the submission is published once, as an integration event carrying the application identifier, in the same transaction that records it"
Fingerprint: d918241d34ce01e4
Verdict: amend
Reason: AC3 asks for exactly one integration event carrying the application identifier; the locked scenario checked a top-level `applicationId` that the published version 1 payload does not carry (D8 puts it in `payload.creditApplicationId`), so it could not pass, and the customer was not yet related as `self`, so the submission would be refused (D6, same as AC1). The new version keeps the exactly-one assertion, the event type filter and the equality of the identifier with the response, only moving the check to the field the contract has and adding the precondition, so it is no weaker.
