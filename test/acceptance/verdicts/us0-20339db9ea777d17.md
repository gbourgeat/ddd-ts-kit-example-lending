# Verdict on scenario "#US0.05 AC3 the submission is published once, as an integration event carrying the application identifier, in the same transaction that records it"

Story: US0
Subject: scenario "#US0.05 AC3 the submission is published once, as an integration event carrying the application identifier, in the same transaction that records it"
Fingerprint: 20339db9ea777d17
Verdict: amend
Reason: AC3 asks for one integration event carrying the application identifier, published once. The locked scenario called `submitted.recorded()`, a method the EventRecorder does not have, so it could not typecheck or run; the current `submitted.received()` is the recorder's method for the events received so far, in order, which is what the scenario meant. The assertions are unchanged (exactly one event, `applicationId` equal to the response identifier), so the new version is not weaker; the transactional part of AC3 is asserted in neither version, which the owner may want to cover later.
